# Transaction types

Over time, the Sila network has undergone various upgrades and improvements to enhance transaction efficiency, security, and user experience. Five significant transaction types that have evolved are:

- Legacy Transactions,
- SIP-2930 Transactions,
- SIP-1559 Transactions,
- SIP-4844 Transactions,
- SIP-7702 Transactions

Each of these transaction types brings unique features and improvements to the Sila network.

## Legacy Transactions

Legacy Transactions (type `0x0`), the traditional Sila transactions in use since the network's inception, include the following parameters:
- `nonce`,
- `gasPrice`,
- `gasLimit`,
- `to`,
- `value`,
- `data`,
- `v`,
- `r`,
- `s`.

These transactions do not utilize access lists, which specify the addresses and storage keys to be accessed, nor do they incorporate SIP-1559 fee market changes.

## SIP-2930 Transactions

Introduced in [SIP-2930](https://sips.sila.org/SIPS/sip-2930), transactions with type `0x1` incorporate an `accessList` parameter alongside legacy parameters. This `accessList` specifies an array of addresses and storage keys that the transaction plans to access, enabling gas savings on cross-contract calls by pre-declaring the accessed contract and storage slots. They do not include SIP-1559 fee market changes.

## SIP-1559 Transactions

[SIP-1559](https://sips.sila.org/SIPS/sip-1559) transactions (type `0x2`) were introduced in Sila's London fork to address network congestion and transaction fee overpricing caused by the historical fee market. Unlike traditional transactions, SIP-1559 transactions don't specify a gas price (`gasPrice`). Instead, they use an in-protocol, dynamically changing base fee per gas, adjusted at each block to manage network congestion.

Alongside the `accessList` parameter and legacy parameters (except `gasPrice`), SIP-1559 transactions include:
- `maxPriorityFeePerGas`, specifying the maximum fee above the base fee the sender is willing to pay,
- `maxFeePerGas`, setting the maximum total fee the sender is willing to pay.

The base fee is burned, while the priority fee is paid to the miner who includes the transaction, incentivizing miners to include transactions with higher priority fees per gas.

## SIP-4844 Transactions

[SIP-4844](https://sips.sila.org/SIPS/sip-4844) transactions (type `0x3`) were introduced in Sila's Dencun fork. This provides a temporary but significant scaling relief for rollups by allowing them to initially scale to 0.375 MB per slot, with a separate fee market allowing fees to be very low while usage of this system is limited.

Alongside the legacy parameters & parameters from SIP-1559, the SIP-4844 transactions include:
- `max_fee_per_blob_gas`, The maximum total fee per gas the sender is willing to pay for blob gas in wei
- `blob_versioned_hashes`, List of versioned blob hashes associated with the transaction's SIP-4844 data blobs.

The actual blob fee is deducted from the sender balance before transaction execution and burned, and is not refunded in case of transaction failure.

## SIP-7702 Transactions

[SIP-7702](https://sips.sila.org/SIPS/sip-7702) transactions (type `0x4`) were introduced in Sila's Pectra fork. This provides the ability for a wallet to delegate its execution to an authorized smart contract. Alongside the fields present from the SIP-1559 transaction type, SIP-7702 transactions include:
- `authorization_list`
- `signature_y_parity`
- `signature_r`
- `signature_s`

where `authorization_list` is a list of authorizations, which are tuples containing the following fields:
- `chain_id`
- `address`
- `nonce`
- `y_parity`
- `r`
- `s`
